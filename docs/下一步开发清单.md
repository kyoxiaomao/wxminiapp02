## 一、P0-1：users 集合 + 登录记录（✅ 已完成 2026-10-12）

### 要做什么

每次启动登录时自动记录用户信息与登录时间，用户无感知。这是 P1-8 账号体系的地基。

### 1. 建 `users` 集合

| 字段名 | 类型 | 中文含义 | 示例值 |
|---|---|---|---|
| `openId` | 文本 | 用户唯一标识（微信 openid） | `oXy7...` |
| `firstLoginAt` | 文本 | **首次登录时间**（只在新建记录时写一次） | `2026-10-10 20:30:00` |
| `lastLoginAt` | 文本 | 最近一次登录时间（每次登录刷新） | `2026-10-12 09:15:00` |
| `loginCount` | 数字 | 累计登录次数（每次 +1） | `3` |
| `createdAt` | 文本 | 记录创建时间 | `2026-10-10 20:30:00` |

- 索引：`openId`（唯一）
- 权限：仅创建者可读写（默认即可）

### 2. 改 `login` 云函数

在现有逻辑（返回 openid + 归属迁移数据）后追加 upsert（有则更新、无则新建）：

```
if (users 里已有该 openId 的记录) {
  lastLoginAt = 现在
  loginCount += 1
} else {
  新建记录：openId + firstLoginAt + lastLoginAt = 现在, loginCount = 1
}
```

注意：使用 `db.collection('users').where({ openId }).update()` + 失败则 `add()` 的经典 upsert 写法，或 `update` 带 `upsert: true`。

### 3. 部署与验证

- [ ] `tcb fn deploy login --force` 部署
- [ ] 模拟器启动两次 → 用 MCP 查 `users` 集合：应有 1 条记录，`loginCount: 2`，`firstLoginAt` 不变、`lastLoginAt` 刷新

### 验收要点

- [ ] 首次登录生成记录，firstLoginAt 落下
- [ ] 再次登录 loginCount 递增、firstLoginAt 不被覆盖
- [ ] 登录失败不影响小程序启动（users 写入挂了不能拖死 login）

## 二、P0-2：图谱上云（✅ 已完成 2026-10-12）

### 要做什么

把 `graphs / nodes / edges` 三个集合建好、迁数据、store 图谱部分云化，让图谱改动（拖动、pin、新建节点/关系）持久化。

### 1. 建 3 个集合

字段按 [CloudBase数据集合设计.md](./CloudBase数据集合设计.md) 第二/三/四节，每个集合都加 `openId` 归属字段：

| 集合 | 索引 | 迁移数据量 |
|---|---|---|
| `graphs` | `id`（唯一）、`openId` | 1 个（陈氏家族图谱） |
| `nodes` | `id`（唯一）、`graphId`、`openId` | 13 个 |
| `edges` | `id`（唯一）、`graphId`、`openId` | 12 条 |

迁移数据同样先写 `openId='test-openid'`，login 云函数的归属逻辑扩展到这三个集合。

### 2. store 图谱部分云化（复用卡片的方案 A）

- `loadGraphsFromCloud()`：启动预加载 graphs/nodes/edges 三集合
- 写穿透方法：`createGraph / updateGraph / deleteGraph`（级联删节点和关系要一并同步云端）、`createNode / updateNode / deleteNode`（级联删关系）、`createEdge / updateEdge / deleteEdge`
- `syncRoleToNodes / syncRoleToCard`（称谓同步）会连带写 cards，注意双集合写穿透的顺序

### 3. 关键决策点：节点坐标要不要存云端？→ 已选 B（存坐标，2026-10-12）

| 方案 | 做法 | 取舍 |
|---|---|---|
| ~~A. 不存坐标~~ | ~~每次打开图谱用放射树初始布局~~ | 未采用 |
| **B. 存坐标 ✅** | nodes 已加 `x/y/pinned` 字段，拖动结束防抖 400ms 写云端 | 布局持久；**拖动语义改为「拖到哪钉在哪」**（原来是释放回弹，会被物理力拉走，无法持久） |

实现要点：
- 引擎 `ForceGraph` 构造时优先恢复保存的坐标/pin（seed 布点后复位），pinned 节点跳过积分=冻结保位
- 拖动结束（含拖一半改双指捏合）→ 节点钉在落点 + `store.saveNodeLayout`（内存立即生效，云端 400ms 防抖合并写）
- 长按按钮的临时 pin、纯点击均不破坏持久 pin（零扰动原则保持）
- 新节点/未拖过的节点无坐标 → 走放射树 seed 布点（自愈）

### 验收要点

- [ ] 新建图谱 → 杀掉重进还在
- [ ] 图谱里新建节点/连线 → 重进还在
- [ ] 删除图谱 → 其节点和关系一并消失（云端也删干净，不留孤儿数据）
