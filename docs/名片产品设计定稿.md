# 名片产品设计定稿（探讨结论）

> 整理自 2026-10-07 产品探讨，作为后续云化改造与名片模块迭代的设计依据。

## 一、平台能力边界（微信硬限制）

| 信息 | 个人主体 | 企业认证主体 | 说明 |
|---|---|---|---|
| 手机通讯录 | ❌ 不可读 | ❌ 不可读 | 无读取 API，隐私硬限制；仅 `wx.addPhoneContact` 单向写入 |
| 手机号 | ❌ | ✅ | `getPhoneNumber` 需企业认证，服务端 code 换取，0.03 元/次 |
| 真实昵称/头像 | ❌ 静默获取 | ❌ 静默获取 | `getUserProfile` 已被收回（2022-10 起返回匿名数据） |
| 头像一键带入 | ✅ | ✅ | `<button open-type="chooseAvatar">` |
| 昵称一键填充 | ✅ | ✅ | `<input type="nickname">`，体验接近自动获取 |
| OpenID/UnionID | ✅ | ✅ | `wx.login` 静默获取，仅作用户标识 |

**结论**：「根据通讯录自动初始化名片」不可行；用户自身名片可用「一键带入头像 + 一键填充昵称 + 手填其余」完成初始化。

## 二、名片批量导入备选方案

| 方案 | 说明 | 成本 |
|---|---|---|
| A：vcf 文件导入 | 用户从系统通讯录导出 .vcf → 发微信文件传输助手 → `wx.chooseMessageFile` 选文件 → 解析 vCard 批量建卡 | 免费，推荐首选 |
| B：OCR 图片导入 | 截图通讯录/拍纸质名片 → 腾讯云 OCR → 建卡 | 少量调用费用 |
| C：自建 + 分享认领 | 首进生成「我的名片」，其余靠分享认领或手动添加 | 零成本 |

注：批量导入拿不到亲属称谓/关系，家族图谱仍需手动归组标关系。

## 三、名片模型（核心定稿）

**概念上名片只有一种：源卡片。分享即引用，改源卡则所有持有者自动同步（「永不过时」）。**

### 数据层两种形态（现实决定，非设计冗余）

1. **本人持有的活名片**：有账号源头，改了全量同步
2. **无主静态卡**：代录长辈、OCR 录入等无源头场景，由代录人维护

活名片本质是账号的投影——没有账号的人（如不上小程序的奶奶）无法拥有活名片。

### 活名片机制

- 本地只存 `refCardId` 引用，不存内容，渲染时拉取最新版本
- 源卡修改 → 版本号 +1 → 所有持有者同步
- 源卡可撤回分享（撤回后持有者侧变灰或锁定末版，待拍板）
- **备注层**：持有者可叠加私有备注（昵称、分组、备忘），与权威数据分层合并展示

### 隐私粒度

> ⚠️ 2026-10-10 更新：「分享字段勾选 / 字段授权」机制已取消（用户认为无必要），分享按**整卡**进行；下文「字段视图」方案保留存档，勿再实现。

**一张源卡 + 按图谱/接收对象授权字段视图**（复用现有「分享字段勾选」机制），而非维护多个版本：

- 分享给家族图谱：勾选 电话/生日/微信号
- 分享给同事图谱：勾选 电话/公司/职位

## 四、图谱群裂变方案

```
A 创建图谱 → 分享卡片到微信群（带 graphId）
  → 群成员点开 → 「认领你的名片」
  → 填写/补全自己信息 → 勾选对图谱成员可见的字段 → 授权
  → 同时获得图谱内所有「已授权可见」的他人名片
  → 新成员又可建新图谱再分享（裂变）
```

**合规红线**：名片必须「认领 + 授权」，不可由创建者单方面录入他人信息后送出（《个人信息保护法》，且微信审核盯此类传播）。每个人的激励：填 1 份自己的，换 N 份别人的。

## 五、待拍板问题

1. 源卡 A 能否看到「谁持有我的名片」？（可见性 vs 隐私感知）
2. 撤回分享后，持有者侧变灰锁定还是保留最后版本？
3. 无主静态卡能否「升级合并」为活名片？（B 后来自己认领了，代录卡与本人卡以谁为准？）
4. 源卡误改即时全量传播，是否需要修改历史/撤销机制？

## 六、实现前提与路线

- 引用同步、图谱共享均**必须后端**；推荐微信云开发（个人主体可用，云数据库 + 云函数够用，免自建服务器）
- 现阶段本地 Mock（`src/store`）即起预留：卡片数据结构增加 `source: 'manual' | 'shared'` 与 `refCardId` 字段，上云免迁移
- 建议落地顺序：云化后端（图谱/名片/授权关系上云）→ 群分享进入 + 认领流程 → 活名片同步机制 → 备注层

## 七、现有可复用资产

- 「分享字段勾选」机制 → 直接升级为「按图谱授权字段视图」
- 图谱类型（家族/公司/学校/通用）→ 与裂变场景天然匹配（家族群→家族图谱）
- 名片模板体系 → 源卡字段结构不变
