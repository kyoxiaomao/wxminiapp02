## P3 应用场景与解决的实际问题

- **痛点**：
  - 纸质名片、群里换的名片，发完就过时，改了电话没人知道
  - 群里刷屏换名片，存进通讯录后就再也没更新
  - 长辈不用小程序，家人的电话、生日、称谓散落在各处
  - 微信不开放通讯录和好友关系，「自动导入好友」根本不可行
  - 《个保法》红线：不能替别人录入信息再送出去
- **应用场景**：
  - 家庭：家族图谱，爷爷奶奶到孙子孙女一图看清
  - 公司：同事汇报关系树，职级关系一目了然
  - 社团 / 客户圈：自定义关系图谱
- **我们的答案**：活名片（分享即引用，永不过时）+ 关系图谱（把人和关系画出来）

## P4 功能简介

- **一键授权建档**：一个按钮授权手机号，头像/昵称一键带入，30 秒建好自己的名片
- **名片管理**：输入即保存，风格模板（淡紫/靛蓝/森绿/暖橙）只换视觉不藏字段，全字段展示，电话一键拨打、微信号一键复制、左滑删除、搜索 + 按时间/按姓名排序
- **分享与互换**：转发名片给好友，对方收下时自动回赠名片，一次分享完成双向交换
- **活名片**：收到的名片带「更新红点」，源卡一改，所有持有者看到的都是最新版
- **关系图谱**：家族图谱、公司图谱、自定义图谱，节点直接关联名片
- **个人中心**：我的名片、我的图谱、意见反馈、隐私说明

## P5 两大核心功能（作品的心脏）

### 活名片 —— 「永不过时」的名片
- 概念上名片只有一种：**源卡片**；分享 = 引用，不复制内容
- 改源卡 → 版本更新 → 所有持有者自动同步，再也不用挨个通知换号码
- 双态展示：本人是编辑态（直接编辑），对方是浏览态（可预览对方视角）
- 更新红点：对方改了信息，列表红点提示，点开即达最新

### 关系图谱 —— 把关系画出来
- Canvas 自绘力导向引擎：斥力 / 弹簧 / 向心 / 代际分层，长辈朝上、晚辈朝下
- 手势全支持：单指平移、双指捏合缩放、拖动节点、点击看详情、长按改关系
- 家族放射树（以我为中心）、公司汇报树（只显示职级关系）
- 图谱节点关联名片，称谓按图谱分别管理（同一个人在家族是「弟弟」，在公司是「实习生」）

## P6 技术开发方案

- **前端**：Taro 4 + React 18 + TypeScript + Sass，一次开发编译为微信小程序
- **后端**：微信云开发 CloudBase，免自建服务器
  - 云数据库：cards / graphs / nodes / edges / users 五个集合，openId 归属隔离
  - 云函数：login（登录与数据归属）、getCard（活名片跨账号读取）、getPhoneNumber（手机号授权换取）、seed（测试数据）
  - 云存储：头像、照片统一存云端 fileID
- **关键技术点**：
  - 自研 Canvas 2d 力导向引擎（与网页 demo 参数 1:1 调优）
  - 引用同步：本地只存 refCardId，打开时拉源卡最新版
  - 名片互换：幂等设计，重复触发不产生重复条目
  - 数据先落云端再写本地，杜绝「新建完在、重启就没了」的假持久化
- **工程实践**：AI 辅助全流程开发 + 真机验收清单 + 调试日志系统

## P7 创新点

1. **活名片机制**：分享即引用、改一处全员同步——名片从「一次性纸片」变成「持续在线的服务」
2. **图谱群裂变（合规设计）**：图谱分享到群 → 成员认领自己的名片 → 授权后互换；坚持「认领 + 授权」，不替别人录入信息，符合《个人信息保护法》
3. **自研力导向关系图谱**：纯 Canvas 手绘引擎 + 家族放射树 / 公司汇报树布局，手机上拖得动、玩得起来
4. **全家 AI 结对开发模式**：爸爸定架构、孩子提需求做验收、AI 写代码——把学 AI 落到一个真正上线的作品上
